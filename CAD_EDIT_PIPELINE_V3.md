# CAD Edit Dataset Pipeline V3

V3 adds a conservative structural deletion branch on top of V1 parameter edits and V2 add-only structural edits.

The current V3 scope is intentionally narrow:

- implemented: `delete_hole`
- not implemented: delete slot, delete pocket, delete boss, replace hole with slot, arbitrary geometric deletion

The training task remains:

```text
input:  original dimensioned three-view drawings + natural-language delete instruction
output: edited executable CadQuery code after deleting the target structure
```

`P1` is generated by deterministic code-block deletion from `P0`. The MLLM is only used after validation to generate a natural-language delete instruction.

## Version Boundary

- V1: parameter-level numeric edits.
- V2: add-only structural edits through appended CSG blocks.
- V3: high-confidence structural deletion through source code block deletion.

V3 does not rewrite V1/V2. It adds a separate deletion branch:

```text
scripts/generate_cad_edit_delete_dataset.py
```

## Flow

```text
CADExpert-style JSONL
  |
  v
1. Extract P0 and images
  |
  v
2. Locate high-confidence delete_hole code blocks
   -> outputs/cad_edit_v2_delete_candidates.jsonl
  |
  v
3. Delete the exact source span to produce P1
  |
  v
4. Execute P0 and P1 with CadQuery and run delete-specific validation
   -> outputs/cad_edit_v2_validated_delete_edits.jsonl
  |
  v
5. Generate instruction after validation
   -> outputs/cad_edit_v2_delete_instructions.jsonl
  |
  v
6. Assemble final training records
   -> outputs/cad_edit_v2_delete.jsonl
```

The output file names retain the `v2_delete` prefix for compatibility with the existing scripts, but this document treats the deletion branch as V3.

## Candidate Schema

A delete candidate describes the existing source block to remove:

```json
{
  "candidate_id": "v2del_000001_001",
  "images": ["./image/Circles/3002_1.png", "./image/Circles/3002_2.png", "./image/Circles/3002_3.png"],
  "original_code": "import cadquery as cq\nresult = ...",
  "delete_candidate": {
    "candidate_type": "structural_delete",
    "edit_type": "delete_hole",
    "source_api": "hole",
    "block_span_start": 65,
    "block_span_end": 98,
    "block_text": ".faces(\">Z\").workplane().hole(12)",
    "replacement": "",
    "parameters": {
      "diameter": 12.0
    },
    "deletion_strategy": "chain_suffix",
    "expected_effect": {
      "volume": "increase",
      "bbox": "stable",
      "operation": "remove_subtractive_feature"
    },
    "instruction_template": "删除零件上直径为 12.0 的圆孔，其余结构保持不变。",
    "instruction_hints": {
      "operation": "delete",
      "human_feature_name": "圆孔",
      "diameter": 12.0,
      "delete_verbs": ["删除", "移除", "去掉"],
      "preserve_other_geometry": true
    }
  }
}
```

Candidate rows intentionally do not contain `target_code` or `validation_report`.

## Supported Delete Patterns

### Single Chain Suffix

Supported:

```python
result = cq.Workplane("XY").box(80, 60, 20).faces(">Z").workplane().hole(12)
```

Deleted block:

```python
.faces(">Z").workplane().hole(12)
```

Target:

```python
result = cq.Workplane("XY").box(80, 60, 20)
```

### Simple Loop Hole Block

`data.jsonl` often creates repeated holes with a simple loop:

```python
result = cq.Workplane("XY").circle(39).extrude(27).faces(">Z").workplane()
for i in range(3):
    result = result.rotate((0,0,0), (0, 0, 1), 120.0).moveTo(15, 0).hole(6)
```

V3 deletes the workplane suffix and the loop together:

```python
.faces(">Z").workplane()
for i in range(3):
    result = result.rotate((0,0,0), (0, 0, 1), 120.0).moveTo(15, 0).hole(6)
```

This avoids leaving `result` as a workplane context instead of a solid.

The candidate records:

```json
{
  "deletion_strategy": "simple_for_hole_block",
  "parameters": {
    "diameter": 6.0,
    "count": 3
  }
}
```

## Skipped Cases

V3 skips cases that are not high-confidence:

- `.pushPoints(...).hole(...)`
- `.rarray(...).hole(...)`
- `.polarArray(...).hole(...)`
- non-numeric hole diameter
- nested helper functions
- arbitrary `.cut(...)` feature deletion
- deletion that makes P1 fail parsing or CadQuery execution
- deletion that changes bbox unexpectedly
- deletion whose changed region looks global

## Code Generation

V3 uses exact source span deletion:

```python
target_code = original_code[:block_span_start] + original_code[block_span_end:]
```

It does not use union plugs to fill holes as the primary method.

## Validation

`validate_delete_edit` checks:

- `P0` executes and yields non-empty geometry.
- `P1` executes and yields non-empty geometry.
- `volume_delta > 0`.
- bbox remains stable.
- edited bbox does not collapse.
- `edited_shape.cut(original_shape)` is non-empty.
- changed-region bbox is not global.
- changed-region volume roughly matches `volume_delta`.

Failures are skipped by default.

This strict validation is important for polygon samples: many polygon examples in `data.jsonl` place holes near or across the outer boundary. Deleting those holes can change the outer bbox, so V3 rejects them as low-confidence.

## Instruction Generation

The shared instruction generator now distinguishes:

- `parameter`: V1 numeric edits.
- `structural_add`: V2 add-only edits.
- `structural_delete`: V3 delete edits.

For `delete_hole`, MLLM instructions may use:

- 删除
- 移除
- 去掉
- 填充

They must not say:

- 添加
- 新增
- 开槽
- 打孔
- 替换

The MLLM prompt receives:

- original three-view images;
- original CadQuery `P0`;
- delete candidate / edit record;
- validation summary.

It does not receive `target_code`.

## Commands

Generate delete candidates, validated edits, fallback instructions, and final records:

```powershell
conda run -n cadedit-v1 python scripts/generate_cad_edit_delete_dataset.py --input data.jsonl --output outputs/cad_edit_v2_delete.jsonl
```

Audit:

```powershell
conda run -n cadedit-v1 python scripts/verify_cad_edit_delete_candidates.py --input outputs/cad_edit_v2_delete_candidates.jsonl
conda run -n cadedit-v1 python scripts/verify_cad_edit_validated_delete_edits.py --input outputs/cad_edit_v2_validated_delete_edits.jsonl
conda run -n cadedit-v1 python scripts/verify_cad_edit_dataset.py --input outputs/cad_edit_v2_delete.jsonl
```

Generate MLLM instructions after validation:

```powershell
$env:DASHSCOPE_API_KEY = "<your Bailian/DashScope API key>"
conda run -n cadedit-v1 python scripts/generate_cad_edit_instructions.py --input outputs/cad_edit_v2_validated_delete_edits.jsonl --output outputs/cad_edit_v2_delete_instructions.jsonl --model qwen-vl-plus
```

Assemble final MLLM-instruction data:

```powershell
conda run -n cadedit-v1 python scripts/assemble_cad_edit_dataset.py --validated-input outputs/cad_edit_v2_validated_delete_edits.jsonl --instructions-input outputs/cad_edit_v2_delete_instructions.jsonl --output outputs/cad_edit_v2_delete.jsonl
```

Render before/after previews:

```powershell
conda run -n cadedit-v1 python scripts/render_cad_edit_pairs.py --input outputs/cad_edit_v2_delete.jsonl --output-dir outputs/cad_edit_v2_delete_renders
```

## Current Limitations

V3 is intentionally conservative. It does not yet support:

- deleting arbitrary `.cut(...)` features;
- deleting slots, pockets, bosses, or pads;
- deleting arrayed holes created by `pushPoints`, `rarray`, or `polarArray`;
- replacing holes with slots;
- generating edited three-view images.

Replacement should be implemented later as delete + add after independent feature recovery is stable.
